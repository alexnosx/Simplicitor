# Codex review of the 2.1.0 implementation plan

Reviewed 2026-10-09 for Alex and Opus. This is a companion review, not an implementation plan or authorization to execute tasks.

- Plan: [2026-10-09-release-2.1.0.md](../superpowers/plans/2026-10-09-release-2.1.0.md), branch `plan/2.1.0`, commit `9725462ba5a3df5295601ed612c999170a5626d8`.
- Code baseline: main / v2.0.0, commit `7793d61c12f5f07556406f67489055f27eaf467b`.
- The planning branch adds only the plan. The review compared it with current source and official WiX, Microsoft, and Qt references. No tests, builds, installers, uninstallers, Windows Sandbox, or install/uninstall/delete tests were executed.

The plan needs corrections before implementation, mainly in MSI authoring, qualification, and CreateScreen integration. The PDF approach, MSI goal, two modes, and mockup approval gate fit Alex's decisions. Keep the original plan unchanged until Alex reviews these corrections.

## Proposed corrections

1. **Keep prohibited tests on the hosted runner.** B3 requests local `test_build_script.py`, which includes file-deletion tests. C2.6 requests the full suite locally. Replace those commands with hosted-runner checks and identify permitted local checks explicitly. Keep PDF failure-cleanup checks on the runner where they exercise file deletion.

2. **Fix MSI component authoring and nested-folder removal (B2).** The pinned WiX harvester creates file key paths for `<Files>`, rather than the HKCU registry key paths expected by ICE38 under user-profile directories. The definition supplies only a root `RemoveFolder`; it does not author removal for the payload's nested directories. Empty subdirectories can prevent B4's install-folder removal check from passing. Generate proper per-user components with HKCU key paths and cleanup entries for their directories. Suppressing validation does not add that cleanup. See [WiX Files](https://docs.firegiant.com/wix/schema/wxs/files/), the [pinned harvester](https://github.com/wixtoolset/wix/blob/v5.0.2/src/wix/WixToolset.Core/HarvestFilesCommand.cs), and [Microsoft ICE64](https://learn.microsoft.com/en-us/windows/win32/msi/ice64).

3. **Make upgrades recoverable (B2).** The default `MajorUpgrade` schedule removes the previous version before the installation transaction. A failed upgrade can leave neither version installed. Use `Schedule="afterInstallInitialize"` so Windows Installer can roll back removal of the previous installation. See [WiX upgrade scheduling](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/).

4. **Give B4 one complete script structure.** "Keep lines 1-62" conflicts with "replace everything from Invoke-Setup onwards": `Invoke-Setup` starts at line 30 in the current [qualification script](../../scripts/qualify_windows_installer.ps1). A replacement fresh-profile check can call `Find-UninstallEntry` before its definition. Define functions before use, then run the checks. Preserve the Ollama-absence probe, environment restoration, and failure when the test app cannot stop. Quote MSI paths, prevent automatic restarts, and retain MSI logs for failed hosted checks. Require the intended MSI instead of choosing the first matching file.

5. **Identify installed MSI products by ProductCode and context (B4).** Combining two registry locations and counting display names can count two records for one installed product. Under StrictMode, entries without `DisplayName` can cause errors. Use Windows Installer product identity, or deduplicate verified registrations by ProductCode. Check installed version, install location, and current-user context, not only the name "Simplicitor."

6. **Strengthen upgrade qualification (B4).** The 2.1.1 probe is a valid MSI major-upgrade test, but contains the same 2.1.0 executable. Assert that the old ProductCode disappears, the new registration reports 2.1.1, the executable still matches the payload, shortcuts still work, and the app still starts. Keep MSI version and executable version separate in the report. Retain a same-version reinstall check.

7. **Define CreateScreen's complete public interface (C2.4/C2.6).** Matching signal names is insufficient. MainWindow still calls `_workspace.set_busy()`, which disappears with CreateWorkspace. It also expects `set_generating`, `clear_status`, `clear_prompt`, `show_open_file_btn`, `set_template_loaded`, and `set_model_small`. Its generation completion callback passes `secondary` and `tooltip` to `show_status`; ExtractionPanel's method accepts only two arguments. Specify these methods and update MainWindow to one screen reference. Avoid dual aliases, which connect the same `retry_requested` signal twice. See [MainWindow](../../simplicitor/app/main_window.py), [CreatePanel](../../simplicitor/app/widgets/create_panel.py), and [ExtractionPanel](../../simplicitor/app/widgets/extraction_panel.py).

8. **Rewrite control wiring instead of moving methods unchanged (C2.4/C2.5).** ExtractionPanel's methods reference removed controls such as `_request_edit`, `_inspect_btn`, `_suggest_btn`, `_confirm_btn`, and `_setup_widget`. The skeleton omits existing state initialization and invalidation. Preserve busy guards, supported-file filtering, clearing stale inspection/confirmation/review, and acknowledgement reset. Disable Next until automatic inspection finishes. The generation signal must carry the selected save folder rather than always using `settings.generated_dir`.

9. **Preserve navigation state and test the connected flow (C2).** `_refresh()` recreates the step indicator and resets it to step zero; `set_steps()` adds another stretch each time. Preserve the current page and rebuild steps only when the route changes. Add MainWindow-level checks for one generation request, one proposal request, pending inspection, cancellation, completion, template use, and Save As. Replace old tab-specific assertions while preserving their behavioral coverage.

10. **Isolate tests and screenshots from Alex's real profile (C2.4/C2.6/C2.7).** `Settings(tempfile.mkdtemp())` changes only the configuration location. Default document/template folders still resolve under the real Documents folder, and MainWindow performs startup job cleanup using application data. Isolate the profile and all configured folders before constructing MainWindow, including in the screenshot script. Use workspace test directories. The Review screenshot can use synthetic Candidate/ReviewCell data as C2.5 does; it does not require a live model run. Keep the separate native extraction walkthrough as an integration check. See [Settings defaults](../../simplicitor/app/config/settings.py) and [MainWindow startup](../../simplicitor/app/main_window.py).

11. **Finish the PDF failure and layout contract (A1/A2).** Qt is suitable and needs no new dependency. Checking only `%PDF` can accept incomplete output. Validate the temporary PDF using the existing pypdf dependency before replacing the destination, and release the writer on failure before cleanup. Preserve single line breaks inside paragraphs, add a multipage/end-of-document check, and verify actual GenerateWorker execution. Remove the output path from the new error log because generated filenames can contain confidential prompt text. Keep the model/source text escaped as the proposal already does.

12. **Make task integration and documentation consistent (B3-B5/D1).** B3 changes the installer format before B4/B5 update qualification and workflow consumers, so intermediate main pushes fail. Integrate that route coherently. Update every `package_payload` caller, including [license tests](../../tests/test_packaged_license.py) and [notice tests](../../tests/test_third_party_notices.py), to the new tuple argument. In B5 and D1, commit before pushing and verify the run for that exact commit. Align the stated Python version with the current 3.11 CI build. Regenerate REPO_MAP after structural changes, update the architecture/UI specifications, and retain the sectioned-file review warning in the 2.1.0 notes. Translate coverage messages as well as selected-cell evidence; moving `_set_coverage` unchanged retains technical identifiers and codes.

## Four open points

| Open point | Finding and recommendation |
|---|---|
| WiX terms | WiX 5.0.2 uses MS-RL. The maintenance fee starts with v6 and does not apply to pinned v5. Generated installer packages normally remain outside MS-RL. Record this and narrow B1's "any additional condition" gate to an actual fee or incompatible obligation. Record that published consumer security support for v5 ended in February 2026. References: [pinned license](https://github.com/wixtoolset/wix/blob/v5.0.2/LICENSE.TXT), [fee policy](https://docs.firegiant.com/wix/osmf/), [licensing and support](https://docs.firegiant.com/wix/). |
| Per-user registration | Expect a current-user ARP entry keyed by ProductCode, with Windows Installer bookkeeping potentially also visible under UserData. These are not independent installed products. Verify identity and installation context through Installer APIs on the runner. No MSI installation was performed during review. Reference: [Microsoft inventory guidance](https://learn.microsoft.com/en-us/windows/win32/msi/inventory-products-and-patches-). |
| ICE validation | Fix ICE38 key paths and ICE64 directory cleanup. ICE91's per-user-location warning can be an intentional, documented exception for a strictly per-user package. Do not blanket-suppress all three. References: [ICE38](https://learn.microsoft.com/en-us/windows/win32/msi/ice38), [ICE64](https://learn.microsoft.com/en-us/windows/win32/msi/ice64), [ICE91](https://learn.microsoft.com/en-us/windows/win32/msi/ice91). |
| PDF fonts | The font-folder setting is justified for Windows offscreen Qt: it uses FreeType, whose font directory honors QT_QPA_FONTDIR. Set it before QApplication, verify fonts are available, and describe it as Windows-specific. References: [Qt offscreen implementation](https://github.com/qt/qtbase/blob/6.11/src/plugins/platforms/offscreen/qoffscreenintegration.cpp), [font-directory implementation](https://github.com/qt/qtbase/blob/6.11/src/gui/text/qplatformfontdatabase.cpp). |

## Parts that need no correction

`Scope="perUser"` is valid in WiX 5.0.2. WiX 5 supplies a default feature, so the absence of an explicit Feature is valid. A fixed UpgradeCode and keeping user data outside the MSI payload are appropriate. The C1 approval gate before Qt redesign is correctly stated.

This review recommends changes for Alex and Opus to assess. It does not establish a passing MSI build, installer qualification, PDF rendering result, or UI integration result, and does not authorize implementation, merging, tagging, or publication.
