### F1 details and the prompt-paragraph decision

The repaired resolver addresses the reproduced default-list-style error and the false routing decision when slides repeat their inherited fonts. The added two-master fixture also covers both effective capture and routing when slides repeat their own master's theme fonts. The extra property-precedence check confirms that an explicit false bold value remains false, while unset size and color still inherit from the default paragraph style.

My previous recommendation to read layout placeholder prompt paragraphs did not define a sound inheritance rule for several prompt paragraphs at the same level. I withdraw that part of F1. The list/default style correction remains valid and is implemented. Claude's counts from Office templates are supporting evidence reported by Claude, not measurements verified in this review. This acceptance does not require copying a layout's prompt content into the generated deck.

### F2 and the three added color fixes

The own/effective distinction is preserved in the code and in the revised decision text. B1 tests cover both inherited background with unchanged text (layouts kept) and inherited background with slide-local fonts (look captured). B3 adds a saved-output check of the master background `0B3D2E`, the retained white title color and the summary. That tests the corrected route through the unchanged shared preparation function.

The added color handling is consistent with that fix:

- Theme slots are resolved through the selected slide/layout/master color map. The dark-map fixtures preserve black backgrounds and white text for master and layout mappings. The extra precedence check confirms that a nearer explicit slide override wins.
- The lighter variant fixture produces `F2DCDB` from accent 2 with lumMod/lumOff. An additional darker neutral-color check produces `404040` from `808080` at 50% luminance. These exercise the newly added math without changing the renderer.
- Background style references use the documented base-color approximation. The plain light-color marker remains distinct from absence while choosing the effective inherited background, then is normalized for the captured plain default. This fits the declared bounded capture behavior.

I found no new blocking defect in these changed paths. Their rendered appearance still belongs to Alex's B3 judgment.

### F3, B3 and B4

The new corrupt PNG is a useful regression fixture: its header and checksums remain recognizable, while its pixel stream cannot decode. It exercises the failure Image.open alone missed. The preparation and import tests inspect the written ZIP package as well as the summary; a merely successful import is not treated as proof that corrupt bytes were removed.

B3 and B4 continue to use the same prepare_template implementation. Revision 3 strengthens their tests rather than adding another preparation route. B4's existing write-failure cleanup and sanitized logging tests still pass. The changed engine documentation accurately describes per-slide context, effective backgrounds and skipping images that cannot fully decode.
