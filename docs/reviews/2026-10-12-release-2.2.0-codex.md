## Required corrections

### R1. [P1] Complete the 2.2.0 version migration before E1

**Location:** plan lines 2530-2534; baseline `scripts/qualify_windows_installer.ps1:165`; `tests/test_build_script.py:80-106,138-165`.

E1 changes only `app/version.py` and says the build-version test keeps passing. That particular test does pass, but two other build tests still use `Simplicitor-2.1.0.msi`, assert `ProductVersion=2.1.0`, and have a fake compiler write the old filename. The reproduced failures are `test_build_produces_matching_portable_payload_and_msi` and `test_failed_msi_validation_prevents_archive`.

The hosted qualification script also fixes the upgrade probe at `2.1.99`. After installing 2.2.0, that is a downgrade. The current WiX package blocks it, so the major-upgrade assertion will fail. This is a prediction from the code and version rules, not a locally executed installer test. [Windows Installer ProductVersion](https://learn.microsoft.com/en-us/windows/win32/msi/productversion) compares the three numeric fields; [WiX MajorUpgrade](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/) blocks lower versions by default.

**Correction:** derive build-test paths, fake outputs and version assertions from `build.PRODUCT_VERSION`. Add the qualification script to the planned files and derive a probe strictly higher than the actual version, with a preflight assertion. Verify that derivation with a source-only test for 2.2.0; do not weaken downgrade protection or run qualification locally. The existing E1 hosted milestone must prove the resulting upgrade path.

### R2. [P1] Background ownership is not a sufficient routing rule

**Location:** plan lines 1349-1358 and 2409-2411, B1 `look_is_on_slides` and B4 `import_template`.

The predicate examines only slide-local backgrounds. A normal white-background deck can have all its branding in its slide text and repeated logo while retaining the default fillable layouts.

**Reproduced:** a three-slide deck with Georgia titles, Verdana body text and a repeated logo yields `look_is_on_slides=False` and `captured=False`. Import strips its slides; the resulting template has Calibri in its theme and no master logo. B1 can capture the original Georgia font and logo, but B4 never uses that capture. This contradicts the table's promised treatment of decks built slide by slide.

**Correction:** keep original layouts only when they carry the relevant look. The selector must account for slide-local fonts/colors and repeated logos, not just backgrounds, with tests for a white-background manual deck and a genuine branded master/layout deck. Share the selector with B3. Preserve original layouts where they do carry the design; do not solve this by discarding every company template's layouts without a product decision.

### R3. [P1] A damaged embedded image still aborts a readable deck

**Location:** plan lines 1265-1271, 1275-1280, 1301-1303 and 1331-1346, B1 image handling.

`_picture` protects `shape.image`, but image decoding is lazy. Accessing `image.ext` later can raise outside that protection; the picture-fill path does the same. B2's injected malformed `Fill` starts after the failing capture step.

**Reproduced:** Presentation opens a synthetic four-slide deck whose image part contains invalid bytes. Both `capture_style` and `import_template` raise `UnidentifiedImageError`, instead of skipping that image. The broken-relationship test passes because it exercises a different failure.

**Correction:** validate/read the image metadata and blob inside the guarded helper, and use it consistently for background shapes, fill relationships and logos. Skip unreadable image data while retaining the remaining style. Add an end-to-end import test with a readable deck containing damaged embedded bytes, plus linked/unsupported-image coverage. Do not catch disk write failures as image degradation.

### R4. [P2] Capture effective paragraph formatting, not only explicit run formatting

**Location:** plan lines 1176-1185 and 1370-1379, B1 `_run_style` and sampling.

Runs commonly inherit their font, size and color from paragraph defaults or their placeholder/layout. The current code interprets missing run properties as theme defaults immediately.

**Reproduced:** a deck with paragraph-level Georgia 36 pt, bold white titles and Verdana body text is captured as Calibri, no title size and black title text. This is independent of R2: it also happens when slide-local backgrounds correctly select capture.

**Correction:** resolve at least the normal run-to-paragraph and placeholder/layout/master/theme inheritance chain for the properties being claimed. Include paragraph-default and inherited branded-placeholder fixtures. Use the effective size for free-form title detection as well. Unknown properties can degrade honestly; reporting a default font as a captured source font is misleading.

### R5. [P1] The B3 gate must judge the route that B4 will ship

**Location:** plan lines 1897-1912 and 1943-1953.

`sample()` labels the predicted route but always calls `capture_style` and builds the generic captured template. Even the company template is captured "anyway for comparison". Thus a passed sample can hide a bad product route, as in R2; conversely, a failed capture comparison can count against a deck the app would render correctly through its own layouts.

**Correction:** the client-ready gate output must follow the actual shared selector and template-preparation path. Optional capture-only comparisons should be separate and excluded from the 8-deck decision. Move the small shared preparation/selection logic earlier if needed; GUI integration can remain after the gate. Use deterministic content compatible with the selected manifest, without calling an LLM.

Keep Alex's threshold and one fix round. Record exactly eight anonymized results with source type, actual route and applied/skipped capture components. Missing outputs, import failures, repair prompts and unreadable/clipped results count as failures; rerun the same full set after the fix round. Include white-background manual styling, inherited fonts, nonuniform/picture backgrounds and non-16:9 output in the eight-deck coverage. The short sample alone does not prove long model-generated content will fit; use representative text lengths within the declared field limits.

### R6. [P1] Reject a sample output location that can overwrite an input

**Location:** plan lines 1897-1933, B3 output handling.

The helper accepts the same input/output folder. If an input is named `client-source-sample.pptx`, producing the sample for `client-source.pptx` replaces that original input.

**Reproduced:** with those two synthetic inputs and `main(folder, folder)`, the original sample-named input's SHA-256 changes. No real deck was used. The example command uses separate folders, but the public helper has no guard.

**Correction:** reject resolved input/output overlap that can replace a source before writing anything. Add a regression that refuses the same-folder case and proves both input hashes unchanged. Keep the default separate output folder; this needs a narrow path check, not a new file-management system.

### R7. [P1] Sanitize the import failure logs touched by B4

**Location:** plan lines 2427-2431; baseline `template_import_worker.py:52-63` and `config.py` import diagnostics.

The new captured write-error wrapper includes the source-derived template slug and raw exception text. The existing worker logs the entire exception; application logging enables DEBUG, so import/collision diagnostics containing the slug are also recorded.

**Reproduced:** a captured-template write failure with a synthetic `Jane-Confidential-Deal.pptx` filename leaves the filename marker in the captured worker log. The new test checks folder cleanup only.

**Correction:** keep file-operation failures actionable in the UI and preserve exception chaining, but log operation/type and exception class only. Remove source-derived names and raw exception text from the touched import diagnostics at every log level. Add a caplog regression for success/collision and captured write failure using a synthetic marker. The separate existing renderer output-path leak is acknowledged by the plan and remains a distinct inherited issue; it is not the only privacy exposure in this route.

### R8. [P2] Narrow A4's warning to what actually happened

**Location:** plan lines 757-767 and 2543, coverage heading and release-note wording.

`_set_coverage` is used for PDF near-zero text, model truncation/request failures and other coverage problems as well as structurally excluded Word content. These paths can retain values in Data.

**Reproduced:** a two-page synthetic PDF has a near-zero page containing `ID 42`. The reader flags `unreadable_page` but retains that unit; a deterministic fake response saves `42` in Data. The new heading says values in those parts are not used for the table. Failed model requests can likewise retain flagged proposals by design.

**Correction:** retain the specific truthful Word exclusion messages, but use a general heading such as "Some information may be missing. Check these reading or processing problems before using the table:" or distinguish omitted structures from processing warnings. Add a retained-value/near-zero-page case and a partial-response case. Change wording only, preserving extraction and flags. Carry the correction into C1/D and E1 notes.

### R9. [P2] Implement the built-in-only GUI outcome, not merely a hidden Upload button

The existing library lists both default and user templates. Hiding Upload leaves previously imported templates visible/selectable and leaves the no-selection help telling users to upload.

**Reproduced:** after the specified hide action, the picker still contains two default entries and a user entry. The one visibility assertion passes without establishing the stated policy.

**Correction:** if "built-in templates only" is the approved drop result, filter the GUI picker to defaults and update the unavailable-upload guidance, while preserving user files and the developer CLI. Test a library already containing both sources, not only button visibility. ## 2.3.0 Word Edit roadmap

The priority, Word-only start, reading view, explicit selection/review and new-file save are a sound direction. It is correctly not executable from this plan. Three matters must be resolved in its separate design:

1. **Selection scope:** the Decisions section says whole paragraphs, while the roadmap adds table cells as single units. Existing cell anchors flatten all cell paragraphs into one source unit. Define whether cells are editable in v1, how replacements map back to their paragraphs, and whether a selection can cross a table boundary. Keeping tables read-only in the first editor is the smaller scope if cell editing has not been approved.
2. **Patch scope:** "change only w:t" and "added paragraphs copy ... properties" are different operations. Decide whether replacement paragraph count may differ and define inserted/deleted runs/paragraphs, tabs/breaks and formatting explicitly. Exclude or preserve section-break and other structural markers; blindly copying a last paragraph's properties can duplicate section properties.
3. **Byte preservation:** reading with python-docx is fine, but ordinary Document.save or whole-part XML reserialization is not proof that document.xml stays byte-identical outside the selection. Retain original package bytes and design a bounded XML patch with frozen selection/anchors. Test lexical byte preservation on documents not authored by python-docx, as well as every untouched part, relationships and unsupported structures. The model should return text-only structured proposals, never editable XML or executable operations.

No 2.3.0 implementation is justified until that design, its mockup and its implementation plan are approved.

Revise the numbered corrections, then keep the proposed sequence: small Part A fixes, bounded Part B capture and a production-representative B3 gate, approved Create mockup/revision 2, Part D, and hosted release qualification. Do not drop template uploads on the basis of the current capture-only gate, and do not treat the 1,089 passing synthetic tests as a client-ready style qualification.
