# Security

## Reporting a vulnerability

To report a security issue, email **alex@thursdaysoftware.com** with a description and reproduction steps. Maintenance is best-effort; there is no formal response SLA. Do not include confidential client documents or secrets in public issues.

## Processing and evidence

[PRD privacy and failure requirements](PRD.md#privacy-and-failure-behavior) govern local processing and diagnostic data. [Project status](docs/PROJECT_STATUS.md) owns known implementation gaps and current release evidence. Do not infer confidential handling from a passing source suite or a valid output file.

Use synthetic or suitably sanitized fixtures. Treat document/model text as data; validation and evidence review must precede the new extraction route's publication. Default-security artifact checks and the reported block are covered by [packaging procedures](docs/code-signing.md#windows-trust-investigation). Do not weaken Windows protection as a remedy.

## Licensing and claims

The [license](LICENSE) and version boundary follow Alex's decision recorded in [PRD.md](PRD.md#license-decision). Local processing does not establish GDPR compliance.
